## 1. Executive Summary & Vision

TradePilot AI transitions from **User-Provided Evidence** (manual screenshot uploads of Orderbook, 3M/6M Charts, Broker Summary, Foreign Flow) to **System-Acquired Evidence** (automated real-time & historical market data ingestion via ZAPI: Pluang, IDX, and Stockbit).

### Core Principles
1. **Zero Upload Friction**: The user enters a stock symbol (e.g., `BBCA`), trading style, and optional notes. TradePilot automatically collects, normalizes, validates, and snapshots the evidence.
2. **Preservation of the "Evidence" Concept**: Evidence is not removed; it becomes authoritative, immutable, system-acquired point-in-time snapshots with exact timestamps and provider provenance.
3. **Structured Tabular Context over Vision**: Context is fed to AI models (Gemini, DeepSeek, etc.) as deterministic JSON/tabular data, eliminating OCR errors, saving ~70% input tokens, and reducing analysis latency by ~70%.
4. **Evidence Delta for Lifecycle Updates**: For `WATCHING_UPDATE` and `OPEN_POSITION_UPDATE`, the system compares current market state against previous snapshots and generates precise "Evidence Deltas" to evaluate thesis changes.

## 3. Data Pipeline & Architecture

```
User Action: "Analisa BBCA"
       │
       ▼
[1. Evidence Collector] ──── Concurrent async calls to ZAPI (4 calls max)
       │
       ▼
[2. Evidence Normalizer] ─── Canonical serialization into Domain Schema
       │
       ▼
[3. Evidence Validator] ──── Completeness & Integrity Checks (Rule Engine)
       │
       ├─ If Incomplete ───► Status: EVIDENCE_INCOMPLETE (Diagnostic UI + Retry)
       ▼
[4. Evidence Snapshot] ──── Stored immutably in DB (#SNP-YYYYMMDD-TICKER-XXX)
       │
       ▼
[5. Context Builder] ────── Formatted into Tabular Markdown Context
       │
       ▼
[6. AI Reasoning Engine] ── Gemini / DeepSeek generates structured Analysis
```

## 4. Evidence Snapshot & Delta Schema

### 4.1 Snapshot Payload Definition
Each snapshot is stored as an immutable JSON document containing:
- `metadata`: snapshot ID, session ID, symbol, capture timestamp (WIB / ISO), provider attribution.
- `quote`: authoritative price metrics.
- `orderbook`: bids, asks, spread, bid/ask ratio.
- `historical_ohlcv`: 130 daily bars + backend-computed technical indicators.
- `foreign_flow`: 1D, 1W, 1M, 3M net flows + accumulation classification.
- `broker_flow`: top buyer/seller matrix + bandarmology concentration.
- `market_context`: macro index metrics.

### 4.2 Evidence Delta Definition (Update Lifecycle)
Generated by comparing Snapshot $N$ with Snapshot $N-1$:
- `price_delta`: difference and percentage move.
- `orderbook_delta`: shift in bid/ask ratio and depth support.
- `foreign_flow_delta`: additional net foreign volume since last snapshot.
- `broker_flow_delta`: changes in lead accumulator broker and concentration.
- `key_events`: human-readable change indicators.

## 5. ZAPI Request Budget & Efficiency Policy

- **Initial Analysis**: Exactly **4 concurrent requests** (`quote`, `orderbook`, `stock-history`, `broker-summary`).
- **Update Analysis (Watching / Open Position)**: Exactly **2 concurrent requests** (`quote/orderbook`, `broker-summary`), reusing 6M historical bars from session memory.
- **Short-Term In-Memory Cache**: 10-second TTL to avoid duplicate calls during rapid UI clicks.

## 6. User Experience & Interface Specifications

1. **New Session Form (`/sessions/new`)**: Single input for ticker symbol with auto-lookup, trading style selector, and optional setup thesis notes.
2. **Acquisition Stepper**: Real-time progress bar (< 1s) validating data fetching from Pluang and IDX.
3. **Evidence Inspector Drawer**: Interactive UI component showing live snapshot badges (Quote, Orderbook, Foreign Flow, Broker Flow) with an expandable drawer for raw tables.
4. **1-Click Refresh Analysis**: Fast update trigger on active sessions that evaluates thesis changes with zero manual input.
